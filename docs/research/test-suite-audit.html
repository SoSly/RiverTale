RiverTale Test Suite Audit

Scope: all 33 files under src/test/java (about 5,800 lines). Each test was read against the production code it exercises and, for ReTerraForged stubs, against .claude/ref/reterraforged. Prepared by Claire on 2026-11-18.

Method and limits. Every claim below comes from reading the code, not from running it. I did not run the suite or mutate production code to prove that a test can't fail. Where a claim depends on code I couldn't see (for example, RTF's Climate.apply), it is marked verify. Before deleting anything, the cheap way to confirm a "can't fail" finding is to break the behavior on purpose and watch whether the test notices.

High severity

H1STUB MISMATCH The empty-sample Cell fixture is physically impossible

Used in FlowlineTracerTest.cell(), RegionalRoutingTest, RegionTransitionTest, PreparationBoundaryTest, RegionExplorerTest.traceEastFrom and fluvialDiscoveryDoesNotPrepareNonCoastalNeighbors, and as RiverWorld's default loader (RiverWorld.java:45).

The tests use new Cell(pos, Set.of()) as a neutral land cell. With no sample positions, though, Cell's derived methods return vacuous or degenerate values:

averageEstimatedTerrainHeight()  // 0.0 / 0 = NaN, and Math.round(NaN) = 0, so the height is 0
isOcean()                        // the loop never runs, so it returns true
isBasin()                        // the loop never runs, so it returns true
averageContinents()              // NaN

A real cell can't be both ocean and basin, and real land at Y=0 would be a basin. These tests pass because RiverGraph only reads feature(), flowDirections() and height(). The consequences are concrete:

  • Every unspecified cell sits at height 0. As a result, the nudge-rise and fall metrics in tests that rely on default cells are measuring an all-zero landscape, and nudgingLimit is never exercised except where a test explicitly uses cellAtHeight.
  • RegionExplorerTest.traceEastFrom runs the real RiverShaping.preclassify. Its hand-set SNOWMELT feature survives only because isOcean() is vacuously true, which makes preclassify return the cell before Feature.classify can run. If Cell ever guards against empty sample sets, the setup's intent silently changes.

Give the harness one explicit land-cell factory (such as a mock or real cell with a real height and isOcean=false), and decide whether Cell should reject empty sample sets outright.

H2TAUTOLOGICAL The test asserts that dead metrics are absent

FlowlineTracerTest.java:361–362

assertFalse(Store.ratios().containsKey(FlowlineTracer.class.getName() + "_retrySuccess"));
assertFalse(Store.timers().containsKey(FlowlineTracer.class.getName() + "_backtracking"));

A grep for retrySuccess and backtracking across src/main finds nothing. These metrics presumably existed before the priority-queue rewrite, but either way the assertions can never fail now. What remains of the test (a valid path and success 1/1) duplicates followsOrderedFlowToTheLandSideOfAnOceanBoundary.

Delete the test, or rewrite it around whatever "retry" means in the current priority-queue search, if that concept still matters.

H3TAUTOLOGICAL Branch reuse is measured at the wrong layer

FlowlineTracerTest.exhaustedBranchesAreReusedAndFailedSearchesAreMeasured (L331–351)

The test counts calls to the cell loader and asserts that visits.get(sharedDeadEnd) == 1. However, the loader is called only during RiverPreparation.prepare, through RiverGraph.cell, which is a computeIfAbsent memo. During trace(), the tracer reads the immutable PreparedRiverData and never touches the loader. The count would be 1 even if the tracer re-expanded the dead end a thousand times.

If branch reuse is a requirement, observe it through the tracer itself (for example, through an expansion counter or metric). Otherwise, rename the test to describe only the failure ratio it actually checks.

H4TAUTOLOGICAL The routingLoads == 0 assertions are vestigial

RegionalRoutingTest.java:111 and :138

The tests reset routingLoads after prepare() and then assert that tracing didn't call the discover function. FlowlineTracer is constructed from PreparedRiverData alone and holds no reference to the provider, so the counter is structurally incapable of changing. PreparationBoundaryTest.traceWithoutLoaders already enforces the real invariant much more strongly, by making every provider static throw.

Drop these two assertions. The rest of each test is meaningful.

H5TAUTOLOGICALSTUB MISMATCH FeatureTest asserts the opposite of its name, and its fixtures pass by accident

FeatureTest.java:43–71

  • classifyPreservesExistingFeature starts with Feature.RUN and asserts Feature.NONE. Feature.classify always overwrites the feature, so "preserves" is false by design. The test asserts real behavior under a name that claims the reverse.
  • Both tests pass watershed = null, and Run returns false on null, so RUN can't match. Each source handler fails for an incidental reason: height 84 is below every source height threshold, and vegetation 0.1 fails Seep. Neither test pins down why nothing matched, so a threshold change could flip them for the wrong reason.
  • The fixture builds Cell(new CellPos(10, 20), Set.of(new ChunkPos(0, 0))) with cellSize = 2. A real cell at (10, 20) would sample around chunk (21, 41). This cell samples a chunk that doesn't belong to it, while hasInflowingNeighbor() computes neighbors from real positions, so the neighborhood is incoherent.

Rename the test or delete it. If Feature.classify needs unit coverage, cover the dispatch order (first matching handler wins) and the ocean short-circuit with stubbed handlers or a coherent cell.

Medium severity

M1TAUTOLOGICAL The test asserts that a stub returns its stubbed value

FlowlineTracerTest.java:661–662

assertEquals(70,  cells.get(new CellPos(3, 2)).averageEstimatedTerrainHeight());
assertEquals(200, cells.get(terminus).averageEstimatedTerrainHeight());

Both cells are cellAtHeight(...) mocks. These lines test Mockito rather than RiverTale. The intent was probably "the tracer didn't mutate input heights," but mocks can't be mutated anyway, and PreparedRiverData copies into immutable CellData.

Delete the two lines.

M2TAUTOLOGICAL FluvialTest asserts things Fluvial can't violate

FluvialTest.noOceanBoundaries; findsBasinBoundary (the allMatch(BASIN) half)

Fluvial.boundaries never calls isOcean(), and its only add call is BoundaryType.BASIN. Asserting "no OCEAN" and "all BASIN" is asserting the shape of the code. The only falsifiable assertion in the file is !isEmpty(), which doesn't check the count, the positions, or that the basin cell itself is skipped as land.

Assert the exact boundary set for the single basin (four land-to-basin edges at known positions).

M3TAUTOLOGICAL The "cold" cache case is never tested

CellFlowTest.coldHighPointIsSnowmeltWithColdOrWarmNeighborCache (L110–118)

The first line after setup is assertFalse(cell.hasInflowingNeighbor()), which computes and caches all eight neighbors with flow. Both following classify calls therefore run against a warm cache, and the cold path in the test's name is never exercised. (classificationIsIndependentOfNeighborVisitOrder in the same file does this correctly.)

Classify first on a fresh cache, then warm it and classify again.

M4WEAK ASSERTION The nudge-before-straight test can't see the order

FlowlineTracerTest.fiveCellFallbackTriesNudgingBeforeGoingStraight (L265–273)

From (1, 2) flowing NORTH toward (5, 2), the candidates are the NORTH step (an away step, rejected at allowance 0), the NE nudge (2, 1), and the direct step (2, 2). Both of the last two reach the terminus, and the test asserts only terminus == (5, 2). If candidate ordering regressed so that the direct step won, this test would still pass. Compare farModeRotatesNonProgressingFlowOneStepTowardTheDestination, which correctly asserts cells().get(1).

Assert path.cells().get(1).equals(new CellPos(2, 1)).

M5STUB MISMATCH Flowlines teleport, and the mocked tracer never moves away

FlowlinePreparationTest.addPath; WatershedPreparationTest.path and its setup

  • FlowlinePreparationTest builds flowlines from pos(x).getMinCell() for each region, so consecutive cells are 8 cells apart. WatershedPreparationTest uses path(0,0, 8,0, 9,0) and path(24,0, 16,0, …), which also jump. Real flowlines are D8-adjacent; WatershedBuilder.findCrossings throws "Flowline cells must be distinct adjacent neighbors" on these. The units under test only look at regions and cell membership, so they happen not to care. Even so, the fixtures describe rivers that can't exist, and the diagonal-crossing logic in WatershedPreparation is only exercised by the single test that happens to use adjacent cells.
  • FlowlineTracer is mocked, but movesAway and awayStepAllowance aren't stubbed, so they default to false and 0. Every reverse step is therefore "approaching," and UpstreamSearch's allowance logic is never in play for these suites.
  • The mocked tracer.region(pos) answers for any position. The real one throws "Incomplete river preparation" for unprepared regions. The mock therefore hides any case where preparation fails to cover a region that gathering later asks about.

Reuse WatershedPreviewTest.path(), which interpolates adjacent cells, and stub region() to throw outside a declared set.

M6STUB MISMATCH RiverWorld departs from production in two ways

RiverWorld.java:44 (default discovered) and :113–125 (classify)

  • Sources ignore inflow. Every traced position becomes a SNOWMELT mock regardless of neighbors. In production, every source handler rejects a cell with hasInflowingNeighbor(). Several tests make mid-river cells into sources: RegionalRoutingTest (8,3) and (8,2), and AwayStepTest expected.get(1). The javadoc documents this, and it's harmless for the tracer. However, any test that reasons about which sources exist (upstream counts, watershed membership) is built on source sets that production wouldn't generate.
  • Discovery is a superset. By default, every region's discovery returns all configured regions. The real RegionExplorer.discover gates by type (FLUVIAL only considers COASTAL neighbors) and by border flow (COASTAL only admits a FLUVIAL neighbor whose border cells flow in). RiverGraph also adds water cells from every discovered region's boundaries, so the superset can change routing as well as reach. Only RegionalRoutingTest overrides this with a hand-built map.

Consider letting the default discover delegate to the real RegionExplorer over the configured regions, and stop forcing sources on cells that have inflow unless a test explicitly asks for it.

M7STRUCTURE-SENSITIVE WatershedPreviewTest pins metrics and call ordering

WatershedPreviewTest.fullPreviewTimesNetworkBuildBeforeOverlayTraces, localPreviewDoesNotTimeNetworkBuild, and the metric block in localModeBuilds… (L364–370)

  • fullPreview… mocks four statics (RiverPreparation, FlowlinePreparation, WatershedPreparation, WatershedBuilder). Inside a fifth (SourceTrace), it asserts that RiverNetwork's build timer has already stopped. That pins the exact nesting of timers rather than any behavior a player or Niv would observe.
  • The local-mode test asserts exact metric keys and values (localSourceRegions = 9.0, localOnly = 1.0, and specific timers present or absent). It also asserts verify(tracer, never()).predecessors(any()), which is an interaction detail. Renaming a metric, or computing predecessors lazily for another reason, would break the test with no functional regression.

Keep the behavioral halves (which paths, which watersheds, and whether remote regions were traced). If metrics are a contract, test them in one place instead of sprinkling them through behavior tests.

M8STRUCTURE-SENSITIVE MetricsCommandTest is a formatter test with a path-statistics name

MetricsCommandTest.reportsPathStatisticsThroughTheCommandAndClearsThemWithOtherMetrics

The test never traces a path. It writes values into Store under hand-typed copies of FlowlineTracer's key strings ("carveFlatFallBlocks" and so on), then checks the formatted output. If FlowlineTracer renamed a metric, this test would keep passing while the real command printed something different. It also asserts messages.size() == 10, which ties the test to the exact number of seeded metrics. The numbers mirror FlowlineProfileTest's first example, which creates the impression of an end-to-end link that doesn't exist.

Rename it to describe what it covers (formatting, header, and clear), and seed it with neutral metric names.

M9STUB MISMATCH The heightmap stub skips the real applyClimate side effects (verify)

RtfSampleProviderTest.setUp, compared with .claude/ref/reterraforged/cell/heightmap/Heightmap.java:56–81

The stubbed applyClimate sets only temperature and moisture. The real method can also rewrite erosion and weirdness, and it ends with:

if (cell.riverMask >= 0.675F && cell.macroBiomeId > 0.5F) {
    cell.weirdness = -cell.weirdness;
}

Because RtfSampleProvider never calls applyRivers, riverMask stays at its constructor default of 1.0. The sign flip then depends only on macroBiomeId, which is presumably set inside climate.apply (not in the ref subset, so verify). If so, production ridges is negated for roughly half the world, while mapsNativeHeightAndClimate… asserts ridges == 0.625 as raw pass-through. The Spring threshold (springMaxRidges) consumes this value directly.

Separately, recordsCoreSamplingCost mocks Store statically to check that a timer named "sampleCore" ticks. This is low-value instrumentation coupling.

Confirm what Climate.apply does to macroBiomeId. If the flip is real, the stub should model it, and the question of whether RiverTale wants folded or flipped ridges becomes a spec question.

Low severity

L1TAUTOLOGICAL Constant and accessor checks

  • RiverTaleTest: these tests assert MOD_ID == "rivertale" and LOGGER != null. Neither can fail in a way that matters.
  • SampleTest.retainsNativeOceanFlag…: this test checks record accessors. (enrichmentPreservesNativeHeight… is worth keeping, because hand-written withers are where copy-paste bugs happen.)
  • CellTest.minimalConstructionCreatesBasicCell, withFlowDirectionsPreservesOtherFields and withFeaturePreservesOtherFields are record and wither checks of the same kind. averageEstimatedTerrainHeightUsesNativeHeight is a one-sample duplicate of the three-sample test above it. isBasinReturnsTrue… asserts its own fixture precondition (estimatedHeight < 63).

L2WEAK ASSERTION CoastalTest's anyMatch assertions

findsOceanBoundary, findsBasinBoundary and findsBothBoundaryTypes pass as long as at least one boundary of the type exists, even if spurious boundaries are present too. Only multipleFacesPerCell is precise. The fixture cells also sample ChunkPos(pos.x, pos.z), which doesn't match the cellSize = 2 layout used in that test's config. This is harmless because the cache is mocked, but it's another incoherent cell.

L3STRUCTURE-SENSITIVE Tests live in the wrong class or reach into internals

  • FlowlineTracerTest contains two pure Flowline tests (returnedPathCannotBeChanged… and lengthCountsCardinalAndDiagonal…).
  • WatershedTopologyTest.replacesOverlappingWatersheds… is a WatershedCache test.
  • CellTest's six samplePositions* tests exercise CellCache.getSamplePositions through the package-private SampleOffset record. Renaming that internal type breaks them.
  • RegionExplorerTest's last four tests (inlandPathCanCross… and following) are end-to-end tracer tests and inherit H1.

L4STRUCTURE-SENSITIVE RegionExplorerTest runs with Strictness.LENIENT

Leniency, combined with broad any(RegionPos) stubs, means that stubs which stop being used produce no warning. It looks like this has already happened. The FLUVIAL branch now checks neighbor types through RegionTypeCache, and the setup's typeCache mock delegates back to regionCache. That delegation looks like a bridge added to keep older tests passing, not a model of production. I didn't check the git history to confirm this.

L5STRUCTURE-SENSITIVE Golden values and change detectors

  • RiverPathInterpolatorTest asserts raised.get(32).targetElevation() == 105 along with other magic values. It's POC code, so this may not matter.
  • CommonConfigTest.partialTomlRetainsCustomValues… restates every default literal (new SourceConfig(175, 0.2, 113, …)). This is intentional if defaults are spec. Otherwise, it's a change detector that must be edited alongside every tuning change.
  • RoutingConfigTest asserts cellCount() == 3 and 4, and AwayStepTest and FlowlineTracerTest.longRoutes… assert exact upstream cell counts. These are fine as long as they're derived from the fixture, but they're opaque to read.

L6STUB MISMATCH Smaller fidelity gaps

  • FlowlinePreviewTest.existingVisCommand… never initializes RiverShaping, so getRandomState() is null. The test avoids an NPE in Crater only because the fixture temperature (0.1) is below craterMinTemperature (0.2), which returns before the random draw. A fixture tweak would turn this into a confusing failure.
  • RegionTransitionTest.naturalCrossings… builds OCEANIC regions with BASIN boundaries. Production never gives an oceanic region boundaries (Region.create returns List.of() for that type). The expected result is false either way, so the matrix still holds.
  • ShoreRoutingTest's mocked Cell stubs isOcean and isBasin independently. The fixture is internally consistent (the water cell is at 55 and only one flag is set per run), but nothing enforces the real coupling between the two flags.

Tests that hold up well

These suites are falsifiable, assert precise outcomes, and use fakes that match production closely enough. They're worth using as templates.

TestWhy it's good
PreparationBoundaryTestIt makes every provider static throw during tracing, so "tracing uses only prepared data" is enforced rather than assumed. This is the best technique in the suite.
WatershedBuilderTestIts seeded randomized trials check structural invariants and input-order independence, which makes it a real property test.
FlowlineProfileTestIt's a pure function with hand-checkable expected lists, including both infeasible branches.
